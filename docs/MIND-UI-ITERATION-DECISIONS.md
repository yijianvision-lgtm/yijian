## 否决与失败原因

### V5-A 整体方案：只认可小地图，不认可整体模型
- 用户认可：小地图的外观/出现方式方向可用；地图需要独立、可选择显示方式。
- 用户不认可：V5-A 的整体模型与布局；左右常驻面板被隐藏后入口太隐蔽，用户找不到。
- 失败原因：把局部可取的地图改进误当成整套 UI 获得认可；整体替换超出用户认可范围。
- 后续处理：不得恢复 V5-A 整套；只抽取地图模块，移植到用户认可的前一版整体模型。

### V6 / V7 / V8 / V9 后续整体 A/B/C
- 用户反馈：A/B/C 的更新没有明显可感知的改善，且整体模型偏离原先认可方向；V8 对四象限的破坏尤其明显。V8-B「知识框架」只有局部可参考，不代表整体获批。
- 失败原因：在没有先稳定获批基线的情况下持续改整体结构；局部结构视图/功能改动影响或遮蔽了四象限主模型，版本差异没有形成用户可识别的有效进步。
- 后续处理：这些后续整体方案不再作为展示基线；不得把树状谱系、网状关系图塞入四象限。树/网结构只允许作为独立视图，在未来得到明确同意后再迭代。

### 错误回滚：误把 V5-A 当成完整满意版本
- 失败原因：把「认可 V5-A 小地图」误读成「认可 V5-A 整体」；随后又错误地以 V5-A 作为整套恢复目标。
- 后续处理：明确采用「V4-A 整体 + V5-A 地图模块」的组合。已撤回误建的 `ui-preview-a5-restored-map-corner.html`，避免混淆。

## 后续每轮的强制工作流
1. 先核对当前获批基线和用户最新反馈，不凭版本号猜测。
2. 先写清楚本轮只改哪些局部，哪些结构/视觉绝对不动。
3. 每轮交付可访问预览；只有 Pages 部署成功才提供线上预览链接。
4. 区分源码提交、自动测试、Pages 部署、真实浏览器视觉验收四种状态。
5. 用户否决后，先追加本文件：失败点、原因、仍可保留的局部、下一条替代路线；不得立即沿原路线再出一个换皮版本。
