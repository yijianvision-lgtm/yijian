# GUANFU MIND｜纲领对齐实施路线图

**版本：1.0｜日期：2026-11-08｜依据：GUANFU-MIND-DESIGN-CHARTER.md V1.1**

本路线图用于把最高设计总纲转成可验收工程任务。它不表示下列功能已经完成，也不授权直接迁移正式用户数据、接入云同步或覆盖正式入口。

## 一、当前真实基线（仓库检查）

- V3-A 是当前视觉候选页；保留深黑三维宇宙方向，不能把预览页当成正式产品已完成。
- 最近提交 `7833653` 已将聚焦核心文字居中、保持四向无框；对应 Jekyll、NEBULA backend checks 和 Pages build/deployment 三项 Actions 均成功。该成功只证明仓库工作流通过，不代表浏览器端到端验收。
- 本地数据层为 IndexedDB `nebula_local_v2`，`DB_VERSION = 5`，当前 22 个 object stores。原始资料和提取队列已有基础结构。
- 已有 `knowledgeRelations`、`relationEvidence`、`reviewProposals`、`knowledgeVersions`、`frameworks`、`frameworkVersions`、`nodePositions` 等记录能力，但并不等于模型已完整实现。
- `getFrameworkTree()` 仍通过知识节点的单一 `parentId` 构建树；`getSpatialProjection()` 的默认语义坐标仍由树深、`knowledgeTime/date` 和 `domain/domainPath` 派生。四维空间投影目前仍是简化版本。
- 当前数据层没有独立的 `ExplorationPath`、`FrameworkMembership/Placement` 或等价上下文记录。路径历史与知识对象身份、多框架归属尚未完整分离。
- `saveKnowledgeRelation()` 主要验证两端节点存在和非自环；关系类型、方向、上下文、证据状态与端点语义的一致性约束仍不足。
- `saveNodeVersion()` 的比较字段不完整，部分属性变化可能无法形成版本快照。
- 资料导入已有 PDF、DOCX、DOC、EMMX、XMind 的初步处理，但 DOC 仅保留原文件并提示另存；PDF 扫描件 OCR、EMMX 层级/图片/关系保真、DOCX 图片和定位、批量预览/冲突处理均需进一步验收。
- 当前测试包含静态契约和语法检查；它们不是完整真实浏览器测试。尚缺覆盖多路径、身份复用、导入保真、备份恢复、权限与隐私边界的完整 E2E 证据。

## 二、必须先守住的架构原则

1. **KnowledgeObject 稳定身份**：知识对象 ID 不由标题、坐标、树路径生成；同一对象可被多个框架和路径引用。
2. **Typed Relation 多对多**：时间先后、影响/因果、内部组成、材料来源、同时代共存、跨领域联系、对照、冲突、互补等必须分型，不允许用单一 parentId 或无类型连线替代。
3. **Framework Placement 独立**：某对象在某个框架中的位置、角色、上下文与排序，不能写回为该对象唯一的全局父级。
4. **ExplorationPath 独立**：记录从哪个焦点、沿什么探索方向、通过哪条关系、基于什么证据进入目标对象；路径可分叉、回退、重访，且不复制知识身份。
5. **Evidence / Provenance 独立**：原始文件、提取片段、定位器、关系证据、用户确认和 AI 推断必须可区分、可追溯。
6. **SpatialProjection 只是视图**：XYZ 坐标、镜头距离、节点邻近不能创建或删除知识关系，也不能决定知识身份。
7. **四向探索与四维定位分离**：四向是递归探索行为；谱系、时间、空间／世界、横向关联是全局定位维度。二者不能混为四个按钮或四个数据库字段。
8. **Local-first 与用户审核**：原始材料不可变；AI 建议不得未经用户确认进入正式框架；任何迁移必须先备份、预览、可回滚。

## 三、阶段计划与完成定义

### P0｜基线冻结与模型规格（约 3–5 个工作日）

- 把 V1.1 纲领拆成实体、关系、路径、上下文、证据和投影的字段级规格。
- 标记 V2.0 旧架构中与 V1.1 冲突的单一 parentId 约束，保留其历史文档身份，不再把它当最终本体。
- 定义关系类型目录、方向规则、证据状态、来源定位器、路径状态和多框架上下文。
- 建立迁移兼容矩阵：旧 graph、旧四向字段、framework rootNodeIds、nodePositions、relationEvidence 如何映射；无法无损映射的项目进入待审核队列。

**验收：** 数据字典、关系语义表、迁移矩阵和测试案例全部经审阅；不触碰真实数据。

### P1｜知识身份、框架上下文与探索路径（约 1–2 周）

- 引入稳定知识对象与框架位置的分离表达；同一对象可加入多个框架或多个上下文。
- 引入可分叉的 ExplorationPath / PathStep；每一步保存 source focus、target object、direction、relationId、evidence refs、context、createdAt。
- 路径回退、分叉、重访同一对象不重复创建对象；对象复用时保留各路径上下文。
- 旧 parentId 仅作为兼容的主要谱系投影，不能再充当唯一全局归属。
- 提供无损 schema migration、迁移前自动备份、迁移预览、校验和回滚。

**验收：** 自动化测试证明 A→B→C 与 A→D→C 最终指向同一个 C 对象，且两条路径均完整保存；同一对象可在两个框架拥有不同位置；迁移前后记录数、附件哈希和关系引用可核对。

### P2｜四向递归与三维聚焦体验（约 1–2 周）

- 四向探索支持每个方向 0..N 个候选目标，且每个目标必须指向稳定对象或明确标记的待确认候选。
- 任意目标进入后成为新焦点，重新拥有完整四向能力；允许返回、分叉、切换历史路径。
- 相机在 XYZ 中连续聚焦目标，保留全局锚点；小地图、路径导航、关系视图与焦点保持一致。
- 四维定位作为独立信息层呈现，不占用四向入口；未知/不适用状态必须明确。
- 按需展开，不能一次性渲染整个知识宇宙。

**验收：** 真实浏览器连续探索至少 10 层；每方向多个目标；同一对象跨路径重访；返回与切换路径不丢上下文；无重叠、点击失效、镜头跳变和控制台错误。

### P3｜关系证据、来源回溯与知识过滤闭环（约 2–3 周）

- 统一关系断言、关系类型、方向、上下文、提出者、状态、理由和证据引用。
- 对时间先后、同时代、影响、因果、组成、材料、创作者/制造者、跨领域关联分别建立规则；不得从时间邻近、同域标签或空间邻近自动推断关系。
- 原始文件与提取候选分离；候选经去重辨异、定位、关系建议、用户审核后才写入正式知识。
- 从节点/关系回到原始文件、页码、标题、段落、原始 EMMX/XMind 节点路径；无法精确定位时标记缺失。
- 版本比较覆盖全部语义字段；合并、拆分、重归位均有预览、变更记录、撤销和来源继承。

**验收：** 每个已确认关系均可查看依据；AI 推断不会伪装为事实；拒绝/暂缓提案不改变正式图谱；合并拆分在测试副本上通过引用完整性检查。

### P4｜导入、备份恢复与长期可靠性（约 1–2 周）

- 分格式验收 PDF、DOC/DOCX、EMMX、XMind、图片及 DeepSeek 导出内容；保留原件、层级、图片、备注、关系和来源定位。
- 对重复文件、重复内容、近似知识、冲突内容提供可解释预览，不静默覆盖。
- 全量备份覆盖所有 stores、二进制原件、关系证据、版本、路径、框架上下文和附件引用。
- 恢复支持校验、冲突预览、合并/替换策略、失败回滚和恢复后完整性检查。
- 本地隐私、浏览器文件授权、持久化存储、容量不足和权限失效均有清晰提示。

**验收：** 使用真实样本文件和测试数据库完成导入→过滤→审核→导出→清空测试库→恢复→逐项比对；原件哈希、节点 ID、关系、路径、版本、附件引用一致。

### P5｜质量门禁与正式启用（约 1–2 周）

- 单元、数据契约、IndexedDB、迁移、浏览器交互、E2E、恢复、隐私与性能测试。
- 至少覆盖桌面 Chrome/Edge 与移动端常见视口；检查可访问性、键盘操作、减少动态效果设置。
- 验证空数据、百万级潜在扩展策略、关系过滤和按需渲染的性能边界；大规模性能目标需用真实样本测量后确定。
- Pages 预览、正式入口和后台服务分别验收；只有用户明确批准后才连接正式后台或覆盖正式入口。

**验收：** 所有阻断级缺陷清零；备份恢复演练成功；隐私与权限边界通过；关键 E2E 全绿；用户逐项确认验收清单。

## 四、工期判断

以当前仓库状态、AI 辅助开发、每轮由用户实际体验反馈、暂不建设账号云同步为前提：

- **可体验的核心版本（P0–P2）：约 2–4 周。** 包含正确的数据边界、真实多路径递归和可用的三维聚焦/定位，不等于完整产品。
- **本地可长期使用的完整 V1（P0–P5）：约 8–12 周。** 预计窗口：2027-01-03 至 2027-01-31。
- **若导入格式保真、复杂迁移、真实文件样本、移动端和性能问题超出预期：预留 2–4 周缓冲，完整验收可能延至 2027-02。**

以上是工程估算，不是保证日期。最影响工期的不是再调 UI，而是旧数据模型迁移、来源证据保真、跨路径身份复用和真实浏览器 E2E。若后续增加账号系统、跨设备私有同步、多人协作、云端文件存储或生产级 AI 服务，必须另行估算，不包含在本轮 V1 工期内。

## 五、当前优先级与禁止抢跑

**下一项实际工程任务：P0 数据模型规格 + 现有代码差异清单。** 先把 KnowledgeObject、FrameworkPlacement、ExplorationPath、RelationAssertion、EvidenceSpan、SpatialProjection 的边界定义清楚，再编写迁移和测试；不得先改数据库 schema 再补设计。

在用户确认 P0 规格前：
- 不对真实 IndexedDB 做破坏性迁移；
- 不覆盖正式入口 `index.html`；
- 不把 V3-A 演示节点写入正式知识；
- 不把 Pages / 静态测试通过宣称为产品完成；
- 不把四向探索简化为每方向单目标；
- 不把四维定位重新塞回四向象限。

**完成的定义不是“网页看起来完整”，而是用户能安全地把资料持续导入、过滤、定位、关联、审核、形成框架、任意回溯与调用，并且每个结果都能说明来路和依据。**
