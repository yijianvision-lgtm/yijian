# MIND 后台隔离与接入门禁

状态：**隔离基线已部分落实；正式后台接入尚未获准。**

本文件是 V42.7 UI 冻结候选与后续后台工程的边界记录。它不代表 Cloudflare 资源已创建、Worker 已部署、用户认证已配置或正式数据已迁移。

## 1. 冻结基线与 UI 隔离

- 当前 UI 候选基线：`ui-preview-v42-7.html`。
- V42.7 是独立预览，不替换 `index.html`。
- V42.7 引用 `./nebula-local.js?env=preview`。
- 本地数据层依据模块 URL 的 `env=preview` 选择 `nebula_local_preview_v1`；正式入口默认使用 `nebula_local_v2`。
- 后续视觉迭代必须生成新的独立预览文件/版本，不直接覆盖 V42.7 基线。
- 预览数据库和正式本地数据库必须分别备份、分别验证；不得将预览样本合并进正式知识库。

## 2. 当前后端真实边界

- `nebula-local.js` 仍是浏览器 IndexedDB 本地数据层；当前 schema version 为 6。
- `deepseek-worker.js` 是 AI/研究服务桥接，不是 MIND 的持久化知识后台。
- Worker 的受支持业务路由在统一入口执行 `NEBULA_SYNC_TOKEN` 校验；`/health` 只返回服务配置状态，不读写知识数据。
- `wrangler.toml` 当前没有 D1、R2、KV 或 Durable Object 绑定。因此不能宣称云端知识数据库、私有文件存储或全局限流已经建立。
- 当前仓库未提供可确认的最终用户身份认证和服务端用户级数据授权体系。共享静态访问令牌不能替代每位用户的身份验证与租户隔离。

## 3. 已落实的数据安全保护

### 完整备份替换恢复

- `replace` 模式必须包含当前全部 IndexedDB stores。
- 只要缺少任一 store，恢复在开启写事务前即失败，并明确提示“当前数据未被修改”。
- 不完整备份仍可选择 `merge`，但不能以缺失表的空数据覆盖现有数据。
- SHA-256 完整性检查继续保留。

### 合并/拆分操作

- 当前知识合并与拆分跨越多个 IndexedDB 事务，尚未达到原子提交/回滚标准。
- 在单事务改造与回滚测试完成前，接受这两类建议会被安全门禁阻止；建议保持 pending，不修改正式知识。
- 解除门禁的条件：知识图谱、版本快照、来源证据、关系、框架位置、探索路径、学习记录及审核状态必须在同一个事务中提交；任一步失败必须整体 abort。

## 4. 正式后台目标架构

推荐在不改变 UI 认知模型的前提下采用：

1. **静态 UI / Pages**：只负责呈现和交互；UI 版本可独立发布。
2. **Workers API**：唯一业务 API 边界；所有写请求必须校验用户身份、权限、请求大小、输入结构与幂等键。
3. **D1**：结构化知识对象、框架位置、关系、来源元数据、版本、审核记录；每张用户数据表都必须有 `owner_id`，并由服务端从已验证身份派生，绝不信任客户端传入的 owner。
4. **R2 私有 bucket**：原始 PDF/Word/EMMX/XMind 文件与大对象；禁止公开 bucket，下载采用短时授权 URL，并验证对象 owner。
5. **身份提供方**：正式用户登录与会话验证必须先选定并完成服务端验证；Worker 不能把静态前端 token 当作用户身份。
6. **迁移适配层**：前端通过稳定的 repository/API 接口读写；本地 IndexedDB 继续作为离线缓存/迁移来源，UI 不直接依赖 D1/R2 表结构。

Durable Objects 只在需要按用户/资源进行强一致协调或限流时引入；不为了“有后台”而盲目增加单一全局对象。

## 4.5 Worker 上游响应体大小保护（本轮新增）

- Worker 不再直接对第三方上游响应调用 `response.json()`；统一经 `readJsonLimited` 流式读取并解析 JSON。
- 同时检查上游声明的 Content-Length 与实际读取字节数；超过 8 MiB 即取消读取并拒绝解析，避免第三方响应异常膨胀造成 Worker 内存压力。
- 已为超限上游响应增加隔离运行时测试，使用 mock provider，不会访问真实 AI 服务。
- 该限制是上游响应体大小边界，不代替用户级限流、配额或账户授权。

## 4.4 Worker 运行时负向测试接入 CI（本轮新增）

- 新增 `tests/worker-runtime.test.mjs`，以 Node 原生 Request/Response 加载 Worker 模块，不需要真实 Cloudflare 资源、真实用户密钥或外部 AI 服务。
- 覆盖公开健康检查、`/coach` 与 `/mnemonic` 的非 POST/未配置令牌/错误令牌/缺少服务端 API Key、`/share` 未授权、其他业务路由未配置令牌、Content-Length 超限、实际流读取超限及不允许的 Origin。
- 测试显式断言负向路径不会调用外部上游服务；另以 mock 响应验证上游响应声明长度超限时被拒绝。
- 已将该测试加入 `.github/workflows/nebula-backend-check.yml`；2026-11-09 的提交 `4c667ae` 对应后台工作流全项通过，包含合同测试、Worker 运行时安全测试和本地数据库运行时测试。
- 同步修正合同测试中 V42.7 inline script 匹配表达式，并将 Worker 请求体限制检查改为直接检查实际源码调用点，避免过度转义导致的假阴性。
- Worker 教练提示词现保留产品原名“瞻前、顾后、左顾、右盼”，不再将“瞻前”写成“前瞻”。

## 4.2 Worker 路由鉴权补齐（本轮新增）

- 复核发现此前 `/coach` 与 `/mnemonic` 只检查 DeepSeek API Key 是否配置，没有校验调用方的 `NEBULA_SYNC_TOKEN`；这会使持有 Worker URL 的调用方绕过其他业务路由的令牌门禁。
- 现已在这两个路由调用 AI 服务前增加 POST 方法检查、服务端令牌配置检查和 Bearer 令牌比对；失败分别返回 405、503 或 401。
- 该修复统一的是现阶段共享令牌门禁，不代表最终用户身份认证或租户隔离已经完成。生产后台仍须采用经服务端验证的用户会话并由服务端派生 owner_id。
- 此修复尚待 CI 与 Worker 运行时负向测试验证；不得仅凭代码提交宣称部署已生效。

## 4.1 Worker 请求体保护（本轮新增）

- 所有 POST 请求在 JSON 解析前执行流式请求体上限检查，最大 1 MiB；超限返回 HTTP 413。
- 同时检查 Content-Length，并在读取请求流时累计实际字节数，不能只信任客户端声明长度。
- 该限制只解决请求体大小边界，不等于速率限制、用户身份认证或账户级授权。
- Cloudflare Rate Limiting / Durable Objects 限流策略仍需在独立测试环境配置并进行并发验证；当前不得将静态共享令牌描述为用户身份体系。

## 5. 接入前验收门禁

正式数据接入前，以下项目必须全部通过：

- [ ] 确认身份提供方、登录流程、会话刷新与退出机制。
- [ ] 测试环境 D1 与正式 D1 完全分离；测试 R2 与正式 R2 完全分离。
- [ ] 每个读写端点都由服务端鉴权，并从会话确定 owner_id。
- [ ] 用户 A 无法读取、修改、删除用户 B 的任意记录或文件（跨租户负向测试）。
- [ ] API 限流、请求体大小限制、输入校验、审计日志与幂等写入通过测试。
- [ ] 完整备份、校验、预览、恢复、失败回滚与恢复后计数核对通过演练。
- [ ] 本地到云端迁移先 dry-run，列出新增/冲突/跳过/文件校验和；用户确认后才写入。
- [ ] 迁移不删除、不覆盖正式资产；旧本地数据在云端验收前保持可用。
- [ ] V42.7 冻结 UI 可连接测试 API；后续 UI 新版本不会改变 API 契约。
- [ ] 回滚演练证明可切回本地数据层，且云端数据不被清理。

## 7. 不可突破的保护边界

- 正式资产默认只读；未经用户明确授权不得批量写入、删除或覆盖。
- 不以重建数据库、清空数据或重建知识图谱替代修复。
- 私人讲义与原始文件默认归属上传用户，其他用户不可搜索、读取、下载或分享。
- 任何迁移必须可预览、可审计、可回滚；先测试环境，后正式环境。
