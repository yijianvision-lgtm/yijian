## 二、逐项定义

### 01｜最高层法则：保留
现行操作顺序保持为 **定其位 → 联其缘 → 生其相 → 归其一**。本轮不把「道 → 一 → 万象 → 归一」升级为新的操作流程，也不另建并列流程。道生一等哲学思想可作为理念背景，但不替换现行法则。

### 02｜四向探索：合并
四向统一为：
- **瞻前**：沿时间向过去追溯起源、前提、历史条件及相关因素。
- **顾后**：沿时间向后追踪继承、演变、后续影响与历史结果。
- **向内**：深入对象本身，分析定义、构成、材料、结构、工艺、机制及形成主体。
- **向外**：将对象放回同时代及更广阔世界，探索跨人物、领域、地域、制度与学科的关联。

旧有「前瞻、顾后、左顾、右盼」中的有效含义纳入此统一定义，不再作为另一组独立方向。四向可无限递归，不预设固定层数或每方向结果数量；不要求每个对象必须填满四向。每个新对象都可成为新的探索中心。

### 03｜四维定位：新增
四维回答对象在整体认知宇宙中的位置：
1. **谱系**：框架、层级、主干、分支、上下位和上下文归属。
2. **时间**：历史时间、事件时间、时代背景和演变。
3. **空间／世界**：地理、区域、场景、制度环境、文化世界或知识领域；不同语义需区分。
4. **横向关联**：跨层、跨分支、跨框架、跨文献和跨学科的有类型关系。

四维是定位和观察维度；四向是探索行为。二者不得混为同一组按钮或字段。未知、不适用和待确认状态应如实保留。

### 04｜知识对象：合并
在既有稳定知识节点、来源、版本和审核对象基础上，整合：稳定身份、名称与别名、当前认可解释、核心题眼、底层矛盾、边界、框架上下文、四维定位、内部组成、外部关系、来源与证据定位、认知状态、可选口诀、版本与用户确认记录。

这是产品概念模型，不代表本轮批准具体数据库字段或破坏性 schema 迁移。原始资料、AI 分析和用户确认内容必须分层保存。

### 05｜知识树与关系网络：新增
新增两种互补表达：
- **框架树/谱系视图**：表达特定框架中的主干、分支、上下位和结构归属。
- **关系网络视图**：表达跨层、跨分支、跨领域的多对多、有类型关系。

二者共享稳定知识身份，但不得把所有关系塞进单一树，也不得混成无类型连线。树是框架视图，不是知识本体的唯一形式。空间坐标不决定对象身份、层级或关系是否存在。

### 06｜探索路径：新增
把用户如何抵达知识对象作为独立信息，记录起点、当前焦点、经过对象、进入方向、关系上下文和返回路径。同一对象从多条路径抵达时复用稳定身份；每条路径保留独立上下文。路径可分叉、回退、切换和继续递归，但不自动改变对象的框架归属或关系事实。

### 07｜专业纠错：新增
针对语音识别、文字输入和资料提取中的专业术语、人名、作品名、年代及概念误识，建立流程：

**原始识别保留 → 专业语境分析 → 候选纠正 → 展示理由/来源/不确定性 → 用户确认**

原文必须保留；未经确认不得静默替换。不能确定时保留候选或标记待确认，不得凭专业背景臆造答案。

### 08｜AI 认知分析：合并
将专业领域识别、题眼与底层矛盾提取、知识定位、结构拆解、四向探索建议、四维定位建议、重复/冲突/缺口识别及整体归纳，纳入现有「定其位 → 联其缘 → 生其相 → 归其一」过滤流程。AI 建议必须区分原始内容、用户观点、AI 推断和待确认内容；正式知识变更仍须用户审核。

### 09｜口诀机制：合并
口诀是可选的知识压缩索引。用户可输入，AI 可提出候选；用户确认后才成为正式索引。一个口诀可关联多个对象，一个对象也可有多个口诀。口诀不强制、不替代完整知识、推理与证据，也不得因口诀相似自动合并知识。

### 10｜证据可靠性：暂缓
本轮不建设独立证据评分、来源权重或自动可信度排序引擎。现有来源记录、原文定位、证据状态、不确定性与 AI 推断标识继续保留，不得因暂缓而删除或弱化。未来启动需另行提交范围和验收标准。

### 11｜空间化表达：保留
保留现有空间化表达方向与已确认界面组织。本轮不新增把 DeepSeek 文字代码框、文字四维图、口诀模板或答题模板转译为网站 UI 的方案，也不因此改变当前空间界面、导航或交互。

### 12｜认知回放：合并
认知回放整合现有知识版本历史、学习记录和新增探索路径，呈现知识如何被发现、进入、关联、修订、确认，以及用户理解如何变化。回放只用于查看历史，不自动修改当前知识；恢复旧版本须用户明确执行。

### 13｜视觉规范：保留
维持已确认原版视觉：深黑宇宙、克制低亮度、真实三维空间、柔和受控微光、清晰文字、低干扰小地图与收敛侧栏。未经单独确认，不重做主题、主视觉、Logo、节点样式、光效或导航结构。

## 三、本轮明确不做
- 不修改 index.html、预览页面、CSS 或 Three.js 场景。
- 不修改数据库 schema、IndexedDB 迁移或本地数据。
- 不部署或修改 Cloudflare Worker。
- 不引入云账户、云同步或第三方存储。
- 不建设第 10 项独立证据可靠性体系。
- 不替换现行最高认知顺序，不擅自改动原版视觉。

## 四、下一步顺序
1. 先统一产品架构与概念对象边界。
2. 再明确树、网、四向、四维、路径之间的数据与交互关系。
3. 架构审阅通过后，才进入 UI 设计。
4. UI 设计遵循第 11、13 项保留决定。
5. 后续代码实现须单独列明文件、数据影响、测试与回滚方案。
