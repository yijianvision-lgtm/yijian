# V3-A 聚焦导航修订候选｜不覆盖原稿

**状态：独立 UI 候选，等待真实浏览器检查与用户验收。**
**基线：** `ui-preview-v3-a-cosmos.html`（原稿，未修改）。
**候选：** `ui-preview-v3-a-cosmos-focus-review.html`。
**工作分支：** `ui/v3a-focus-navigation-review`。
**本轮不修改：** 正式 `index.html`、后台 schema、Worker、用户 IndexedDB 数据。

## 1. 找回早期模型的区别

早期 3D 原型 `prototypes/void-starmap.html` 将四向思考明确写为：

- 前瞻：起源、前置条件、历史背景
- 顾后：后续影响、结果、演化
- 左顾：横向联系、跨领域相似概念
- 右盼：反向观点、限制与矛盾

这是围绕一个焦点进行思考的四向提示，不等同于后来的四维框架定位。后续纲领的四维定位是谱系纵向、时间、空间/世界、横向关联。两套语义必须分层表达，不应按方位名称机械互换。

## 2. 本轮界面调整

- 将“当前核心知识”信息块移到聚焦画布右上方，右对齐，避免占据中心轴。
- 将右侧“横向关联”象限下移，与右上核心信息块错开。
- 保留上下左右四个象限和中心坐标轴；在窄屏下另设尺寸与位置。
- 原 V3-A 文件保持不变，修订内容只在独立候选文件中。

## 3. 导航与数据约束

- 点击四个象限仍调用同一套聚焦导航，并使用现有 Three.js 相机平滑过渡到目标节点。
- 修复正式框架加载后方向映射被后续语句清空的问题。
- 上方谱系导航只读取框架父级（根节点没有父级时，回退到第一个直接子级）。
- 下方时间导航只读取具有明确时间关系类型、且关系证据状态为 confirmed 的关系。
- 左侧空间/世界导航只读取明确的空间/位置关系类型，不能从 domain 标签推断空间边。
- 右侧横向导航只读取已确认的非时间、非空间关系。
- 关系必须有 confirmed 状态或至少一条 `relationEvidence.reviewStatus === "confirmed"`；待审、争议和未知关系不作为可点击导航目标。
- 没有可核实目标时保持“尚无已确认定位”，不生成虚构节点。

## 4. 本轮发现的旧代码问题

原 V3-A 的框架加载流程先构建 `directionalMap`，随后又执行 `directionalMap = {}`，导致刚构建的真实节点方向映射被清空。该候选删除了这次清空，并为关系导航增加了证据状态筛选。

原逻辑把空间方向留空是正确的安全底线；本候选只允许显式、已确认的空间关系进入该方向，不会把同领域标签当成空间关系。
