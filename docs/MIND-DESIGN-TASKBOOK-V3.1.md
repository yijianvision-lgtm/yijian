- **保留（old）：** 01 最高层法则、11 空间化表达、13 视觉规范。
- **合并（merge）：** 02 四向探索、04 知识对象、08 AI 认知分析、09 口诀机制、12 认知回放。
- **新增（new）：** 03 四维定位、05 知识树与关系网络、06 探索路径、07 专业纠错。

## 1. 保留的最高认知法则
现行流程保持不变：

**定其位 → 联其缘 → 生其相 → 归其一**

- 定其位：明确对象身份、框架位置和当前上下文。
- 联其缘：识别对象与其他对象之间的真实关系。
- 生其相：依据来源、关系和用户确认结果递归生长。
- 归其一：将局部知识回归整体框架，说明其补充、细化、修正或连接作用。

本轮不以「道 → 一 → 万象 → 归一」替换或并列创建第二套操作流程。

## 2. 四向四维一体：中心题眼与四侧观察

以当前知识对象为中心题眼，先明确它在宏观框架中的位置和层级，再围绕同一题眼沿四侧观察。四向与四维是一体模型，不是两组独立系统。

- **前：源（发生学 / Why）**：历史传统、时代背景、制度与思想环境、时代局限、起点、初始矛盾、前置人物/知识/事件及形成条件；必要时回到具体历史时点复原当时场景。
- **左：体（本体论 / What）**：对象定义、边界、本质、组成、材料、结构、属性、标准、工艺、机制、形成主体及内部演进。
- **右：用（价值论 / How）**：功能、用途、价值、受众、外部条件、同时代/平级知识点、人物事件、跨领域对象及与外部世界的交互。
- **后：流（发展学 / Where）**：已经发生的继承、传播、演变、转折、后续影响、后世评价、历史定位；未来预测须另行标注，不与历史后续混写。

框架与层级贯穿四侧。历史时间、具体时点、当时世界和周围对象是四侧展开的上下文：回到某个历史时点时，既看对象自身，也看当时制度、社会、文化、技术、场景以及周围人物、事件和同级知识点。

规则：不限制层数或方向结果数量；不要求每个对象填满四侧；每个新对象可再次成为中心；时间先后不自动等于因果；同时代共存不自动等于影响；进入新对象时保留来路与返回能力。

## 3. 框架位置、历史时间与世界上下文

| 上下文 | 回答的问题 | 典型信息 |
|---|---|---|
| 框架与层级 | 题眼属于哪个宏观框架、哪一层？ | 框架、主干、分支、上下位、同级 |
| 历史时间 | 发生、持续、转折和后续处于何时？ | 年代、时代、事件时间、演变 |
| 当时世界 | 它当时处于怎样的环境？ | 地理、场景、制度、文化、社会、技术 |
| 周围对象 | 谁/什么与它同时代、平级、影响或受影响？ | 人物、事件、知识点、作品、制度、跨领域对象 |

这些上下文贯穿前源、左体、右用、后流，不构成另一套与四侧并列的独立“四维按钮”或必填字段。领域标签不等于地理位置；同时代不自动等于相互影响；关系必须说明类型和依据。

## 4. 合并后的知识对象概念模型
以稳定知识身份为中心，整合：
- 身份：稳定 ID、名称、别名、对象类型；
- 认知内容：当前认可定义、题眼、底层矛盾、边界与解释；
- 框架上下文：所属框架、谱系位置、上下文角色；
- 定位：时间、空间／世界、谱系和横向关系；
- 组成与关系：内部组成、外部关联、有类型关系；
- 来源：原始文件、原文片段、页码/段落/导图路径；
- 认知状态：草稿、待确认、已确认、待修订；
- 记忆索引：可选口诀及关联对象；
- 历史：版本、变更理由、用户确认和学习记录。

稳定身份不得由标题、坐标或当前路径生成。同一对象可出现在多个框架上下文中；不同语境的主张须保留差异。本任务书只定义概念边界，不授权破坏性数据库迁移。

## 5. 新增知识树与关系网络分层
- **框架树**表达特定框架中的主干、分支、上下位与结构组织。
- **关系网络**表达跨层、跨分支、跨框架、跨领域的多对多关系；每条关系需有类型、方向（适用时）、上下文与理由。
- **空间地图**继续负责三维投影和全局定位；XYZ 不创建知识关系、不决定身份或框架归属。

三者共享稳定知识身份，但语义边界分开。父子边、横向关系边、空间邻近不得混成一种线。

## 6. 新增递归探索路径
探索路径记录“用户如何抵达某个知识对象”，而不是知识对象本身。概念上记录 pathId、起点、焦点、访问序列、每步进入方向、关系上下文、来源引用、时间和返回点。

要求：
1. 同一对象从不同路径抵达时复用稳定身份。
2. 每条路径保留独立上下文和返回链。
3. 路径可分叉、回退、切换、继续深入。
4. 路径不自动改变对象框架位置或关系事实。
5. 认知回放可引用路径事件，不复制一套知识本体。

具体持久化方式留待技术设计阶段评估。

## 7. 新增专业语境识别与纠错
输入来源包括语音识别、键入文本和文档提取。识别专业术语、人名、作品名、年代及学科概念可能存在的误识。

流程：**原始输入保留 → 专业语境分析 → 候选纠正 → 展示理由/来源/不确定性 → 用户确认**。

原始转写始终可查看；AI 建议不得静默覆盖；不能确定时保留候选或标记待确认；用户确认后记录原文与确认结果之间的关系。

## 8. 合并后的 AI 认知分析
将以下能力纳入现有「定其位 → 联其缘 → 生其相 → 归其一」流程：
1. 识别专业领域、语境和术语风险；
2. 提取核心题眼、关键定义和底层矛盾；
3. 定位中心题眼，确认宏观框架、层级、历史时点及当时世界上下文；
4. 围绕题眼生成前源、左体、右用、后流四侧一体分析；
5. 识别重复候选、关系候选、观点冲突和知识缺口；
6. 形成整体归纳，说明对象对框架的作用；
7. 展示原文、来源、AI 推断、不确定性和修改影响；
8. 正式知识修改必须经用户审核。

AI 不得自动合并，不得把推断写成原文事实，不得绕过审核改动正式框架。

## 9. 合并口诀与记忆索引
口诀是可选压缩入口。用户可输入，AI 可分析并提出候选；用户确认后才成为正式索引。一个口诀可关联多个对象，一个对象可有多个索引。口诀不强制、不替代完整知识、论证和证据，也不触发自动合并。

## 10. 暂缓证据可靠性独立体系
本阶段不新增复杂证据评分、来源权重或自动可信度排序引擎。现有来源追溯、原文定位、不确定性与 AI 推断标识继续保留。未来启动时需单独提交定义、冲突处理、审核和验收方案。

## 11. 合并认知回放
整合现有知识版本历史、学习记录与探索路径，呈现知识发现、进入、关联、修订、确认及用户理解变化。回放只用于查看历史，不自动修改当前知识；恢复旧版本须用户明确执行。

## 12. 保留空间化表达与视觉规范
**空间化表达（old）：** 保留当前已确认空间表达和界面组织；不新增 DeepSeek 文字代码框、文字四维图、口诀模板或答题模板的 UI 映射，不重排现有空间交互。

**视觉规范（old）：** 保留原版深黑、安静、克制的宇宙基底；真实 Three.js/WebGL；柔和星点与受控微光；清晰文字；低干扰关系线、小地图和收敛侧栏。不得擅自新增大量星云、星球、轨道、粒子、霓虹或厚重卡片；不得擅改 Logo、主色、节点比例和现有布局。

## 13. 架构关系概览
稳定知识身份是中心；框架树表达结构归属；关系网络表达多对多语义；四向四维一体模型围绕题眼展开前源、左体、右用、后流；框架层级与历史时空上下文贯穿四侧；探索路径记录抵达过程；来源支撑可追溯性；AI 只提出建议；口诀作为可选索引；版本、学习记录和路径共同支持认知回放；三维空间负责呈现与导航。

以上是概念关系，不是已批准数据库 schema，也不代表功能已经实现。

## 14. 执行阶段与验收门

### 阶段 A｜统一产品架构（当前）
交付：本变更清单、统一术语、知识对象边界、树/网/四向/四维/路径关系、AI 认知分析和纠错边界、口诀与回放归属。

验收：四向四维一体关系明确；树与网不混淆；路径不等同知识对象；纠错不覆盖原文；AI 不越权；old 项未被改动；later 项未提前实施。

### 阶段 B｜数据与交互规格
交付：概念实体关系图、关键字段草案、多路径身份复用规则、路径进入/返回/切换/回放状态、纠错与审核流程、与现有本地数据兼容及迁移评估。

验收：明确复用与新增部分；说明迁移、备份、回滚；不破坏原始文件和现有知识；未经用户批准不执行 schema 或正式数据改写。

### 阶段 C｜UI 设计
仅在架构通过后，在原版 UI 基础上表达新增架构。交付中心题眼与四侧一体表达、树/网/地图视图切换、路径导航与回放、纠错建议与确认交互。

验收：原版视觉基线保持；新增能力不挤占三维主空间；交互低干扰、结构清晰；用户逐项确认后才进入代码实现。

### 阶段 D｜工程实现
须另行授权。每次交付列明文件、数据影响、自动化测试、浏览器实测、Actions/Pages 状态、回滚方案和未完成项。本任务书不自动授权阶段 D。

## 15. 最终验收原则
**身份稳定、关系有型、路径可追、定位不丢、原文不改、AI 不越权、视觉不擅改。**
