# NEBULA 用户身份与数据隔离契约（实施前置规范）

状态：**设计契约已定义；身份提供方、验证密钥和云端存储尚未配置；不得据此宣称用户认证或数据隔离已经上线。**

本文件定义从共享 Worker 令牌迁移到真实多用户身份与资源归属校验的最低安全要求。它不授权接入正式用户数据，也不替代身份提供方选型、威胁建模、部署和端到端验收。

## 1. 当前状态与迁移边界

- 当前 `NEBULA_SYNC_TOKEN` 是部署级共享访问令牌，不代表登录用户身份。
- 当前 IP + 路由限流只是临时滥用防护，不是账户配额。
- Worker 不得把客户端提交的 `userId`、`ownerId`、`tenantId` 或类似字段当作可信身份。
- 在身份验证与资源归属校验完成前，禁止启用跨设备云同步、私人讲义云存储或任何用户数据读写 API。
- 现有 local-first IndexedDB 行为保持独立，不得因未来云端鉴权失败而清空或覆盖本地数据。

## 2. 身份断言要求

生产身份接入必须由受信任的身份提供方签发短时效访问令牌。Worker 必须在服务端验证：

1. 签名及允许的算法；拒绝 `none` 和算法降级。
2. 精确匹配受信任的 `issuer (iss)`。
3. 精确匹配本服务的 `audience (aud)`。
4. `exp` 必须存在且未过期；若存在 `nbf`，必须已生效。
5. 稳定、非空的主体 `sub`。
6. 密钥来自固定受信任 issuer 的 JWKS/验证配置；不得接受令牌自带的任意 `jku`、`x5u` 或任意 URL。
7. 密钥轮换、缓存过期、issuer/JWKS 不可用及验证异常必须有明确失败策略；不得降级为共享令牌或客户端身份。

服务端派生身份键：`owner_id = namespace(iss, sub)`。可用不可逆、稳定的服务端映射值作为数据库 owner key；不得直接信任请求体中的 owner 字段。身份提供方尚未选定，因此 issuer、audience、JWKS URL 和最终 owner key 派生算法均为**待配置/待验证**，不能写入猜测值。

## 3. Worker 路由授权契约

- 公共路由仅限明确列入白名单的健康检查及必要预检请求。
- 所有访问用户私有资源的路由必须先验证用户身份，再进行授权。
- AI 代理和公开资料检索是否要求登录，应按产品权限单独定义；即使不要求登录，也不得因此获得任何私有资源访问权。
- `/share` 导入结果在写入前必须绑定已验证的 owner；当前接口仅返回转录文本，不得暗示已安全写入用户资料。
- 所有失败默认拒绝（fail closed），不得因身份服务、JWKS、D1 或 R2 故障而跳过授权。

## 4. D1 数据隔离要求

- 每一条用户私有数据记录必须有服务端写入的 `owner_id`。
- 每个读取、更新、删除和关联查询都必须把 `owner_id` 放入 SQL 条件；禁止先按全局 ID 取记录再仅在前端过滤。
- 更新/删除必须同时匹配 `owner_id` 与资源 ID；零行匹配按未授权/不存在处理，不泄露其他用户记录是否存在。
- 唯一约束、外键及关联表必须考虑 owner 范围；跨用户关联默认禁止。
- 批量查询、搜索、统计、导出、备份、恢复、全文索引和后台任务都必须执行同样的 owner 约束。
- 任何管理员/支持人员访问必须是独立、可审计、最小权限流程，不能复用普通用户身份。

## 5. R2 对象隔离要求

- 对象 key 必须由服务端根据已验证 owner 派生命名空间，例如 `owners/{owner_id}/...`。
- 客户端不能任意指定其他 owner 的对象 key 或完整 R2 key。
- 下载、预览、删除、复制、签名 URL 和导出前必须验证 D1 元数据归属与 R2 key 前缀一致。
- 私有对象桶不得公开列举；预签名 URL 必须短时效、限定单个对象及必要操作。
- 原始讲义、解析文本、缩略图、导出包和备份均继承同一隐私等级。

## 6. 必须通过的负向隔离测试

至少创建两个独立测试用户 A、B，并验证：

- A 无法读取、枚举、搜索、统计、导出或下载 B 的任何记录/对象。
- A 无法更新、删除、移动、关联或覆盖 B 的记录/对象。
- 篡改请求体中的 `owner_id`、资源 ID、对象 key 或关联 ID 不会越权。
- 跨用户批量请求、分页、过滤器、全文搜索、关系图和导出接口均不泄露数据。
- 过期、伪造、错误 issuer/audience、缺少 subject、错误签名和未知密钥令牌全部拒绝。
- 身份服务、JWKS、D1、R2 不可用时，私有数据请求失败关闭。
- 用户登出/撤销后，旧令牌失效；缓存与预签名 URL 不得超出批准的撤销窗口。
- 备份恢复不会把 A 的数据写入 B 的 owner 空间，反之亦然。

测试必须使用合成数据与独立测试资源，不使用真实私人讲义或用户资料。

## 7. 上线门槛

以下全部完成前，状态保持“不可接正式后台”：

1. 用户确认身份提供方及账号生命周期方案。
2. Worker 验证真实签名令牌并服务端派生 owner。
3. D1/R2 测试环境及 owner 约束完成。
4. 两用户正向/负向隔离测试全部通过。
5. 备份、恢复、迁移、回滚和撤销流程通过。
6. 前端 API adapter 完成，local-first 数据不受影响。
7. 浏览器端到端验收、日志脱敏和安全审查通过。
8. 用户明确批准后才允许迁移或接入正式数据。

## 8. 当前不做的事

- 不部署 Worker。
- 不创建或改动 Cloudflare 正式资源。
- 不把共享 `NEBULA_SYNC_TOKEN` 伪装成用户登录。
- 不接受前端传入的 owner 标识。
- 不把 IP 限流称为用户级配额。
- 不迁移、覆盖或上传现有私人数据。


## 9. 已确认的同步与隐私产品决策（2026-11-10）

用户已选择 **B：本地优先＋自主开启云同步（Local-first + Opt-in Cloud Sync）**。本节是强制实施边界：

- 登录只用于认证身份；登录成功、令牌刷新、启动应用或登出/重新登录都不得隐式上传私人数据。
- 本地 IndexedDB 必须保持独立可用；用户不登录也可使用本地知识宇宙。云端服务不可用不得损坏或阻断本地资料。
- 云同步默认关闭。只有用户主动开启，并确认清楚展示的同步范围、数据目的地及影响后，才允许同步所选类别的数据。
- 用户必须能够查看同步状态、暂停同步、关闭同步，并控制云端副本的保留或删除。关闭同步不能导致本地资料被删除。
- 身份提供方仅承担身份验证职责，不得被当作 NEBULA 私人知识、讲义、原始文件或历史对话的默认存储方。
- AI 处理、分享导入和其他单次外部请求不是云同步；每次向外部 AI/服务发送私人内容都必须独立告知内容范围与目的，不能借用云同步授权。
- 未完成密钥管理设计与独立安全评审前，不得声称云端同步具有端到端加密。传输加密、静态加密与端到端加密必须准确区分。

验收必须覆盖：未登录本地使用；登录后无网络上传；默认关闭时零私人数据同步；用户主动授权后仅同步所选范围；暂停/关闭后停止后续同步；云端故障时本地数据完整可用。
